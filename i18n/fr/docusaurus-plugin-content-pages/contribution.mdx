# 2) Modérateurs du forum

Tout comme les autres forums, nous recevons beaucoup de spam. Il existe un certain nombre d'outils qui nous permettent de filtrer la majeure partie du spam, mais parfois une « interaction humaine » est encore nécessaire.

Modérer et nettoyer le forum prend du temps, du temps que nous aimerions bien plutôt consacrer à l'amélioration d'Hydrogen. C'est pourquoi nous recherchons des modérateurs de forum. Intéressé ? Continuez votre lecture !

Exigences :

- Une connaissance de base de Drupal est un plus, mais ce n'est pas obligatoire. L'engagement est plus important.
- Idéalement, nous aurions besoin de 2 personnes situées dans des « fuseaux horaires opposés » (si vous voyez ce que je veux dire) pour une couverture optimale, mais encore une fois, ce n'est pas obligatoire.

Comment ça fonctionne :

Les modérateurs du forum reçoivent des notifications par e-mail du module de détection de spam chaque fois qu'il détecte un message potentiellement indésirable.
Le modérateur ouvre l'e-mail, clique sur le lien et est redirigé vers le message « suspect », puis il/elle vérifie si le message est ou n'est pas du spam.
Si le message est bien du spam, aucune autre action n'est nécessaire (le message a déjà été marqué comme spam et sera automatiquement supprimé après quelques jours).
Si le message est valide, le modérateur clique simplement sur le bouton « publier ».

Par ailleurs, le modérateur devrait vérifier fréquemment qu'un spammeur n'a pas réussi à tromper le module de détection de spam et à publier du spam sur notre précieux forum. Si cela arrive, le modérateur peut simplement marquer le message comme spam et c'est tout.

# 3) Manuel

Hydrogen regorge de fonctionnalités. La plupart sont simples à utiliser et l'interface est assez intuitive. Cependant, il y a plus à Hydrogen qu'il n'y paraît : creusez un peu plus et vous découvrirez qu'Hydrogen peut accomplir des choses remarquables !

Les fonctionnalités « simples » et « complexes » doivent toutes être documentées dans le manuel et, comme de nouvelles fonctionnalités sont ajoutées en permanence, le manuel doit également être mis à jour.

Êtes-vous le genre de personne capable d'expliquer des choses complexes de manière claire et simple ? Rejoignez l'équipe et aidez-nous à mettre à jour le manuel !

# 4) Traducteurs et relecteurs

L'application Hydrogen et le manuel sont disponibles dans plusieurs langues. Certaines traductions sont complètes, mais pour la plupart des langues, il reste encore beaucoup de travail à faire.

Traduire l'application ou le manuel nécessite très peu de connaissances techniques et il vous suffit d'installer 1 ou 2 applications (gratuites) pour commencer.

La version anglaise de l'application et du manuel sert de point de départ, donc une bonne connaissance de l'anglais est indispensable.

Une fois votre traduction terminée, il est toujours bon de faire relire votre travail par une ou plusieurs personnes. C'est là que les « relecteurs » entrent en jeu.

Vous avez une passion pour les langues et les boîtes à rythmes nommées Hydrogen ? Oui ? Alors vous êtes la personne que nous recherchons !

# 9) Corriger des bugs

Oui, Hydrogen a des bugs … et nous pourrions vraiment avoir besoin de votre aide pour les corriger !

Pour pouvoir corriger des bugs, vous devrez :

- vous abonner à la liste de diffusion
- apprendre à utiliser Git (plusieurs bons tutoriels sont disponibles sur Internet : c'est un bon point de départ)
- créer un compte GitHub (pas vraiment obligatoire, mais fortement recommandé)
- récupérer le dernier code source

Nouveaux contributeurs :

Pour faciliter au maximum le démarrage des nouveaux contributeurs, nous avons créé l'étiquette « paper cuts » dans notre suivi des problèmes.

L'idée est d'étiqueter les problèmes « faciles à corriger » avec cette étiquette « paper cuts » afin que les nouveaux utilisateurs puissent rapidement trouver les problèmes « faciles » et se familiariser avec le code en travaillant dessus.

Une fois que vous vous sentez suffisamment en confiance, vous pouvez passer à des problèmes plus complexes.

Cliquez ici pour avoir un aperçu de tous les problèmes « paper cuts »

Contributeurs expérimentés :

Voici comment ça fonctionne :

- rendez-vous sur notre suivi des problèmes et parcourez les problèmes ouverts
- choisissez un bug qui vous intéresse et prévenez-nous que vous allez vous en charger via la liste de diffusion ! (n'hésitez pas à demander des conseils ou de l'aide !)

Une fois que vous avez trouvé une correction pour le problème que vous avez choisi, quelqu'un de l'équipe Hydrogen l'examinera et aura presque certainement quelques remarques/suggestions. Appliquez ces suggestions et votre correctif sera prêt à être ajouté à la branche principale d'Hydrogen.

Pour nous permettre d'ajouter votre correctif au code, nous vous encourageons à faire une pull request Git. Cette façon de travailler nous facilite grandement l'organisation de notre code.

Nous adorons les petits correctifs ! Si vous avez créé plusieurs corrections, veuillez ne pas les regrouper en une seule pull request, mais créez plusieurs pull requests plus petites. Cela facilite grandement l'identification de tout problème qui aurait pu être introduit dans l'un des correctifs.

# 10) Ajouter de nouvelles fonctionnalités

Avoir une idée pour une nouvelle fonctionnalité, c'est bien. Nous envoyer un correctif pour la réaliser, c'est mieux :-)

Laissez-moi reformuler :

Étape 1 : l'idée

Étape 2 : se familiariser avec le code d'Hydrogen, implémenter votre fonctionnalité, la tester, corriger les bugs, la retester, la modifier … vous voyez l'idée :-)

Comme vous pouvez le constater, l'idée n'est qu'une petite partie de tout le processus, et son implémentation peut s'avérer plus difficile que prévu.

La meilleure approche est probablement de se familiariser avec le code en se plongeant dedans et en essayant de corriger quelques bugs en premier.

# 11) Testeurs

Là où il y a du logiciel, il y a des bugs …

Lorsqu'une nouvelle fonctionnalité est ajoutée à Hydrogen, son auteur s'assurera bien sûr qu'elle fonctionne sur son propre ordinateur, mais cela ne signifie pas nécessairement qu'elle fonctionnera sur tous les systèmes (anciens, nouveaux, Linux, OSX, Windows, 32 bits, 64 bits …). Il est donc très important que le plus grand nombre de personnes possible la teste sur différents systèmes et dans le plus grand nombre de conditions possible.

Actuellement, il n'existe pas de plans de test (documents décrivant comment tester un aspect spécifique d'Hydrogen). Cela signifie qu'il n'y a pas de méthode standardisée pour tester Hydrogen. Nous demandons plutôt à quiconque souhaite tester Hydrogen de mettre à jour vers la dernière version et de vérifier que sa configuration fonctionne toujours correctement. De cette façon, nous pouvons détecter les régressions (fonctionnalités qui fonctionnaient auparavant mais qui sont cassées dans la dernière version).

** La dernière version ne peut être trouvée que dans notre dépôt GitHub. Vous aurez besoin de connaissances basiques de Git et de la compilation depuis les sources, mais nous sommes là pour vous aider et vous pouvez bien sûr consulter le wiki.

# 12) Partager des idées

Si vous estimez qu'une fonctionnalité manque à Hydrogen, ou si vous avez une bonne idée pour améliorer une fonctionnalité existante : n'hésitez pas à la publier sur le forum des questions de développement afin que nous puissions en discuter. Une fois que l'idée a mûri, vous pouvez créer un nouveau ticket dans notre suivi des problèmes GitHub et lui ajouter l'étiquette « question ». Nous examinerons votre proposition et verrons ce que nous pouvons en faire.

Important : veuillez ne vous offusquer si votre idée est rejetée. Toutes les idées ne sont pas réalisables ou ne s'inscrivent pas dans la philosophie d'Hydrogen. Il est aussi possible que votre idée existe déjà dans Hydrogen, mais sous une forme différente de celle que vous attendiez.

Si vous créez un ticket GitHub (comme décrit ci-dessus), d'autres personnes qui aiment votre idée peuvent ajouter un commentaire « j'aime ça ! » à votre ticket. Les idées populaires ont plus de chances d'être implémentées rapidement que les idées sans « j'aime », mais ce n'est pas une garantie.
